# LFOs and the MK3 Mod Matrix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Up to 16 project-wide LFOs as mod-matrix sources, edited on the MK3 (SHIFT + SELECT) and in the software (a button next to the Mixer), plus a Hydrasynth-style MK3 mod matrix page (SHIFT + SOLO), saved in the DECKARD block.

**Architecture:** The model gets an `Lfo` type with all the wave maths as pure functions, so the engine, the viewer's picture and the MK3 picture compute the same thing. LFOs live as a DECKARD text field `deckard:lfos` on the project's root object, so undo, copy and Maschine stripping work as they do for mod routes. They are saved as a new section in DECKARD block v6. The engine keeps a small runtime per LFO (its trigger time) that survives `adopt`, and it adds `ModSource::Lfo(n)` to `route_travels`. The MK3 pages are Lua, reading new `View` fields and sending new `Action`s that the viewer handles.

**Tech Stack:** Rust (crates `model`, `doc`, `engine`, `surface`; app `apps/viewer`, egui), Lua 5.4 surface scripts.

**Spec:** `docs/superpowers/specs/2026-10-28-lfos-design.md`. Approved mockups: `.superpowers/brainstorm/98810-1793225271/content/lfo-page.html` and `mod-page-v2.html`.

## Global Constraints

- At most 16 LFOs, numbered by pad: `pad` 1–16. A new project has none.
- Defaults for a new LFO: Sine, Sync on, Rate 1/4, Phase 0°, Level 100%, Quantize Off, Trigger Off, Fade in 1 beat.
- Shapes: Square, Sine, Triangle, Saw, Random. Random holds one value per cycle, seeded from (pad, cycle number) so playback and export match.
- Synced rates (in quarter notes): 4 bars = 16, 2 bars = 8, 1/1 = 4, 1/2 = 2, 1/4 = 1, 1/8 = 0.5, 1/16 = 0.25, 1/32 = 0.125, each also dotted (×1.5) and triplet (×2/3). Free rates are 0.01–20 Hz.
- Phase 0–360°. Level 0–100%. Quantize is Off (0) or 2–32 steps per cycle. Fade in is 0–16 beats.
- Output is `wave × level × fade`, in 0..1. A route maps it onto low..high exactly as it maps Pressure.
- A synced LFO's clock is song ticks: the arrangement position in Arrangement mode (plus the export offset), and ticks since play started in Ideas. A Hz LFO's clock is seconds since play started.
- Only notes that sound fire a trigger. Muted notes, notes kept silent by solo, notes skipped by probability or PROB LOCK, and choke events don't.
- Text keys for sources: `lfo1` … `lfo16`. Field name: `deckard:lfos`. DECKARD block `VERSION = 6`.
- Code and comments follow the house style: terse `///` comments in plain English, as in `crates/model/src/mod_matrix.rs`.
- Run the whole workspace's tests at each commit: `cargo test --workspace` must pass.

## Review Focus

1. **An edit during playback rebuilds the engine** (`adopt`). A triggered LFO mid-fade, or a Random LFO mid-cycle, must carry on rather than restart. The test goes in Task 3.
2. **Deleting a group** shifts every later group's index. Triggers stored as (group, sound) must follow, or turn Off for the deleted group, in the same undo step. The test goes in Task 2.
3. **Removing an LFO that routes still use.** The engine must skip those routes without panicking, and the knob must rest at its own value. The software and MK3 show "LFO n (none)". Tests go in Tasks 3 and 6.
4. **Changing tempo or rate mid-play.** A synced LFO is computed from the position, not accumulated, so it stays on the bar. The test goes in Task 3.
5. **Bad or out-of-range saved text** (a hand-edited or future file). Values must be clamped and bad lines skipped, never panic. The test goes in Task 1.

**Interfaces:**
- Produces:
  - `pub enum Shape { Sine, Square, Triangle, Saw, Random }`. It is `Copy` and `Eq`, with `ALL: [Shape; 5]` in that order (this order matches the MK3 display buttons 1–5) and `name() -> &'static str`.
  - `pub const RATES: [(&str, f64); 24]`: name and quarter notes. The order is plain, dotted, triplet for each of 4 bars, 2 bars, 1/1 … 1/32, named like "1/4", "1/4.", "1/4T". `pub const DEFAULT_RATE: usize` is the index of "1/4".
  - `pub struct Lfo { pub pad: u8, pub shape: Shape, pub sync: bool, pub rate: usize, pub hz: f32, pub phase: f32 /*deg*/, pub level: f32, pub quantize: u8, pub trigger: Option<(usize, usize)>, pub fade: f32 /*beats*/ }`. It derives `Debug, Clone, PartialEq`.
  - `Lfo::new(pad: u8) -> Lfo` gives the defaults. `hz` defaults to 1.0.
  - `pub const FIELD: &str = "deckard:lfos"`. `pub fn to_text(&[Lfo]) -> String` and `pub fn from_text(&str) -> Vec<Lfo>` work one line per LFO. Bad lines are skipped and values clamped. A duplicate pad keeps the first. The result is sorted by pad.
  - `Lfo::cycles(&self, ticks: f64, seconds: f64) -> f64`. Synced: `ticks / (PPQ * RATES[rate].1)`. Free: `seconds * hz`.
  - `Lfo::wave_at(&self, cycles: f64) -> f32`. It applies the phase and quantize: `c = cycles + phase/360`, then if `quantize >= 2`, `c = floor(c*q)/q`. It returns the shape's value at `c` (0..1, Sine `0.5+0.5 sin 2πc`). Random uses `random(pad, floor(c))`, a deterministic hash to 0..1.
  - `Lfo::output(&self, cycles: f64, since_trigger: Option<f64> /*beats*/) -> f32`. It returns `wave_at × level × fade`. With `trigger` set and `since_trigger == None`, it is 0. The fade is `min(1, since/fade)` and is 1 when `fade == 0`.
  - `Lfo::picture(&self, n: usize) -> Vec<f32>`. This is `n` samples of `output` over two cycles, with a triggered LFO drawn from its trigger (so the fade ramp shows). The fade is drawn assuming 1 cycle = the rate's beats, or 1 beat for Hz.
  - `Project::lfos: Vec<Lfo>`.
  - `ModSource::Lfo(u8)` (pad 1–16; still `Copy`). `name(self) -> String` gives "LFO 3". `pub fn choices(lfos: &[Lfo]) -> Vec<ModSource>` lists the three expression sources, then each existing LFO by pad. Keys are `lfo1`…`lfo16`.
