# Zhora Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native instrument that plays one modular voice over CV, listens to it come back, and keeps it in tune.

**Architecture:** Zhora is a native class in `crates/plugins/src/zhora/`. Tuning logic is pure and tested against a simulated oscillator. New `native::Engine` methods expose its CV blocks, and the engine feeds it live input and copies its CV to the CV-only channels. Sounds with Zhora never render ahead, so CV stays aligned with the outputs.

**Tech Stack:** Rust 2024, egui, mlua surface pages. Run cargo through mise: `mise exec -- cargo test --offline -p <crate> <filter>`.

**Spec:** `docs/superpowers/specs/2026-11-09-cv-outs-and-zhora-design.md` (Part 2)

**Requires:** `docs/superpowers/plans/2026-11-09-cv-outputs.md`, complete and merged.

## Global Constraints

- Tune target: every note in the tuned range within 5 cents.
- A failed Tune never replaces the previous table.
- CV skips the master, faders, effects and limiters, and is not in exports or stems.
- `process` must not allocate or block. Pitch analysis runs on a worker thread.
- Parameter ids and the class id are saved in projects: never renumber them.
- A = 440 Hz, MIDI note 69. Use Deckard's existing note naming when displaying notes.
- Level defaults 50%. Glide off by default. Live off by default. Clock division default 1/16.

## Review Focus

- Tune pressed while the transport is stopped. It must run. Pinned in Task 3.
- No signal at all on the input during Tune: fails promptly and keeps the table. Pinned in Task 2.
- A note above the tuned range while Live is on: clamped, flagged, no correction chasing it. Pinned in Task 2.
- Muting mid-note: gate drops, and the tuner keeps reading. Pinned in Task 4.
- A saved table loaded at another sample rate: unchanged, because it stores output values and pitches, not frames. Pinned in Task 1.

### Task 2: Tune, Check and Live, against a simulated oscillator

**Files:**
- Create: `crates/plugins/src/zhora/tune.rs`, `crates/plugins/src/zhora/live.rs`

**Interfaces:**
- Consumes: `pitch::Pitch`, `table::Table`.
- Produces: `tune::Reading = Option<pitch::Pitch>`, `tune::Run::tune() -> Run`, `tune::Run::check(table: Table) -> Run`, `Run::step(&mut self, dt_ms: f32, reading: Reading) -> Step`, `tune::Step { Output(f32), Done(Outcome) }`, `tune::Outcome { Tuned(Table), Checked { worst_cents: f32, off: Vec<u8> }, Failed(&'static str) }`, `live::Trim::new()`, `Trim::update(&mut self, dt_ms: f32, note: f32, table_hz: f32, since_note_ms: f32, reading: Reading) -> f32` (semitones), `Trim::locked(&self) -> bool`.

Sweep: outputs from 0 widening by ±0.04 to ±1.0, 100 ms settle then 50 ms reading at each step. A side stops after two consecutive failed reads or when pitch stops rising. Fewer than 5 good points fails. Verify replays 8 notes spread over the range; any note beyond 5 cents is named in `off` but the table is still kept unless every note fails. `Live`: reading only after 150 ms into the note, clarity at least 0.85, within ±50 cents of the note; moves at most 2 cents per second; total limited to ±30 cents.
