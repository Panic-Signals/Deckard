# Scales and chords (Keyboard and Chords modes)

How Maschine 3 maps scales and chords onto the pads, and where DECKARD's copy comes from.
The code is `crates/lua-host/src/api/scales.rs`; its tables, `crates/model/src/scale_tables.rs`, are
generated by `tools/scale-tables/extract.py` from your own Maschine binary.

## Where the data lives

None of the names are stored as text in the binary: they are built at startup from
UTF-32 constants written straight from registers. Two static initializers build every
table:

- `__GLOBAL__sub_I_Utilities_ALL.cpp` builds `NI::MASCOMMON::ScaleHelper`'s tables:
  - `s_aScaleIncrements`: 120 rows × 12 ints, copied from `__TEXT` with `memcpy`;
  - `s_scalesDegrees`: a vector of `vector<pair<size_t, int>>`;
  - the note-name, chord-set and chord-type string tables.
- `__GLOBAL__sub_I_Modules_ScaleEngine_Objects_ALL.cpp` builds
  `NI::MASCOMMON::DATA::ScaleEngine`'s lists: banks, scale names (full and short), chord
  modes, chord types and chord positions.

`extract.py` loads the arm64 slice into Unicorn and runs both initializers:

- allocation and copy stubs are implemented; the other stubs are skipped;
- the first initializer is stopped once its scale tables are done;
- the second faults after its lists are built, while registering serialization, and the
  fault is ignored.

The tables are then read out of the emulator's memory.

## Scales

- **Banks and types:** 8 banks of 15 scales: Main, Modes, Jazz, World, 5-Tone, Modern,
  Major and Minor. A scale's index is `bank * 15 + type`.
- **Short names:** each scale has a full name and a short one. The full name ("Harmonic
  Minor") is the touched-knob list's; the short one ("Harm Min") goes under the knob.
- **`SNAP[i][k]`:** for the semitone `k` above the root, the offset that moves it onto
  the scale. `0` marks a scale note, so Major is `0,1,0,1,0,0,1,0,1,0,1,0`. The
  ScaleEngine processor uses it to snap notes; the pads use the zeros.
- **Pads (`Song::getNoteForPad`):** pad 1 is the root. The pads go up the scale's notes
  in order and continue an octave higher after the last one. Above note 127 they give
  128, meaning none.
- **Root pads:** pads on the root or its octaves are lit fully, and the others dimmed
  (`PadModeHelper.isRootNote`).
- **Changing bank:** `ScaleEngine::resetScaleIndex` sets the type back to 0, as the
  hardware shows.

## Spelling (`ScaleHelper::getNoteName(root, scale, note)`)

1. **Chromatic:** sharps (`C C# D D# …`) + octave, where MIDI 60 = C3.
2. **The root itself:** the mixed list (`C C# D Eb E F F# G Ab A Bb B`).
3. **Other notes:**
   - A note off the scale has no name.
   - A note on the scale is the n-th scale note. `s_scalesDegrees[scale][n]` gives
     (degree, accidental) relative to the major scale. The letter is
     `(majorRootDegreeOffsets[root] + degree) % 7`. The accidental is
     `accidental + majorScaleIncrements[root][degree]`:
     - −1, 0 or +1 → letter + `b`, nothing or `#`;
     - ±2 → named as the sharp note it sounds as.
   - B# belongs to the octave below the C it sounds as.

The root note is shown with sharps for the chromatic scale and from the mixed list for
any other (`getRootNoteName`).

## Chords

**Chord Mode (`ChordMode`)** has four values:

| Value | Mode |
|---|---|
| 0 | Off |
| 1 | Harmonizer |
| 2 | Chord Set |
| 3 | User Chord |

- **Chords page:** shows `ChordScreenChordMode`, which is the same list without Off.
  CHORDS sets the chord mode from the group's last one (`MK3Helper`); KEYBOARD turns it
  off.
- **Chord type knob:** `CurrentChordType` reads the type kept for the current kind of
  list:
  - Harmonizer with the chromatic scale: Octave, Perfect 4 … Trichord;
  - Harmonizer with any other scale: Octave, 1-3 … 1-4-7, defaulting to 1-3-5;
  - Chord Set: Major 1–8, Minor 1–8;
  - User Chord: Set 1–16, labelled SET.
- **Position (`ChordPosition`):** Auto, -8 … -1, Root, 1 … 8, Auto.
- **Chord set names (`ScaleHelper::getChordSetChordName(set, pad, key, short)`):**
  - The chord's root is `CHORD_SET_ROOTS[set][pad]` above the key.
  - Sharps are used in sharp keys, which differ between the major and minor sets, and
    for Major 8's pads 2 and 4; flats otherwise.
  - A flat root is followed by a space before a type that starts with a letter
    ("Eb add9").
  - A type ending in `/` takes the bass note `CHORD_SET_BASS[set][pad]` above the key
    ("C/B").

## Chord voicings

What a pad plays in Chords mode. Maschine's scale engine (`ScaleEngineProcessor`)
turns each note-on into a chord: the pad sends one note and the engine plays the
chord's notes. DECKARD's code is `deckard_model::chords` (`crates/model/src/chords.rs`).
The tables are in `scale_tables.rs`; `extract.py` reads them from the globals that the
ScaleEngine initializer fills:

- `HARMONIZER_CHROMATIC`: the Harmonizer's chords for the chromatic scale, in semitones;
- `HARMONIZER_SCALE`: its chords for the other scales after Octave, in scale steps;
- `CHORD_SET_CHORDS`: each chord set's 12 chords, in semitones from the pad's note,
  bass first.

In this section *key* means the root note's pitch class (0–11) and *n* means the note
the engine gets.

### The note each pad sends (`Song::updatePadToNoteMap`)

- **Harmonizer:** the pads send their Keyboard-mode notes (the scale up from the root).
  With the pads, the engine's key mode is Mapped: an off-scale note moves onto the
  scale by `SNAP` first.
- **Chord Set and User Chord:**
  - Pads 1–12 send the root note's octave plus 0–11, and the engine adds the key. So pad
    *i* (from 0) gets *n* = root note + *i*.
  - A pad sends nothing if *n* would be above 127. Pads 13–16 send nothing.

### The pattern

| Mode | Pattern | Unit | Octave *O* |
|---|---|---|---|
| Harmonizer, chromatic scale | `HARMONIZER_CHROMATIC[type]` | semitones above *n* | 12 |
| Harmonizer, other scales: Octave | [0, *N*], where *N* is the number of notes in the scale | scale steps | *N* |
| Harmonizer, other scales: type *k* ≥ 1 | `HARMONIZER_SCALE[k − 1]` (1-3 = [0, 2] … 1-4-7 = [0, 3, 6]) | scale steps | *N* |
| Chord Set | `CHORD_SET_CHORDS[set][(n − key) mod 12]` | semitones from *n* | 12 |
| User Chord | the set's chord for pad (*n* − key) mod 12 | semitones above *n* − ((*n* − key) mod 12) | 12 |

- **Scale steps:**
  - Step 0 is *n* itself.
  - Step *s* is the note *s* scale notes above *n*, or below when *s* is negative. The
    scale is played from the key, with octaves going on past its last note.
  - If *n* is not on the scale, every step plays *n*.
- **Out of range:** notes outside 0–127 are not played. A pad whose note is not played
  plays nothing.

The chord set table holds Maschine's voicings, which are not always root position.
Major 1 in C, pad 1, is [−12, 4, 7, 12]: C2 (the bass), then E3, G3 and C4. Pad 2 is
Em: from C#3 it is [−9, 3, 6, 10], which gives E2, E3, G3 and B3.

### Position (`ChordPosition`)

The list has 19 entries: Auto, -8 … -1, Root, 1 … 8, Auto.

- **Entry *i* from 0 to 17:** a fixed position *p* = *i* − 9, so Root is 0. The first
  "Auto" is not Auto: it gives *p* = −9, because Maschine only treats the last entry as
  Auto.
- **Entry 18:** Auto (see the next section).

A position *p* is applied to the pattern with octave *O*. For a chord set, the bass
entry is left out:

1. Nothing changes if *p* = 0, if there are fewer than 2 entries, or if the highest
   entry minus the lowest is more than *O*.
2. If that span is exactly *O* (the top doubles the bottom an octave up), the top entry
   is set aside.
3. Let *m* be the number of entries left. Rotate them left by *p* mod *m* (a remainder
   from 0 to *m* − 1). Then add ⌊(*p* + *j*) / *m*⌋ · *O* to entry *j* (counting from 0,
   after the rotation).
4. A top entry that was set aside comes back as the new lowest entry + *O*.

| Pattern | *p* | Result |
|---|---|---|
| Major [0, 4, 7] | 1 | [4, 7, 12] |
| Major [0, 4, 7] | −1 | [−5, 0, 4] |
| Major [0, 4, 7] | 3 | [12, 16, 19] |
| Octave [0, 12] | 1 | [12, 24] |
| Major 7 [0, 4, 7, 11] | 2 | [7, 11, 12, 16] |

### Auto (`ChordAutoPositioner`)

Auto moves each chord's position towards an anchor chord, so that chords played one
after another stay close together.

**When it applies:**

- Auto applies to every pattern except two, which span more than an octave and play at
  Root instead: Dominant 9 and Quartal, with the chromatic scale.
- The engine checks the Harmonizer's chromatic chord type in every mode, not just the
  Harmonizer. So with the chromatic scale and that type set to Dominant 9 or Quartal,
  the chord sets and user chords also play at Root.

**State:** the anchor (a chord's notes) and the last note played. Any change to a scale
or chord setting clears both: there is no anchor, and the last note becomes 0.

For each note *n*:

1. **New anchor.** If there is no anchor, or *n* is 12 or more semitones from the last
   note, the chord plays at Root and becomes the anchor.
2. **Leading.** Otherwise, start from the Root chord:
   - With fewer than 3 pattern entries it plays as it is.
   - Compare the average pitch of the chord with that of the anchor (a chord set's bass
     is left out of both). The step is +1 if the chord's average is at or below the
     anchor's, and −1 if it is above.
   - While the two averages are 1 or more semitones apart: apply the step to the
     pattern again (it adds up: 1, 2, 3 …) and work out the notes again.
   - If a step moves the chord further from the anchor than the step before, the chord
     from the step before plays. Once the averages are less than 1 apart, the current
     chord plays.
   - The anchor stays as it is.
3. Either way, *n* becomes the last note.

DECKARD stops after 64 steps. Maschine has no limit, but no pattern it allows reaches
it.

## Touched-knob list

**How it works:**

- Touching a knob shows its parameter's values in a list over the screens
  (`CapacitiveOverlayList`, MK3 style `CapacitiveOverlayDefault`).
- The list is used for enum parameters (`getTag() == TAG_ENUM`). Its items are
  `getAsString(i)`, the full names, and it is centred on the current value.
- It is a `Vector<Label>` that the scripts fill through `NI.GUI.connectVector`.
- DECKARD fills the vectors that are on screen after each tick, `max-items` rows from
  the item offset.

**Size and position:**

- The frame is placed with `setPos` and sized with `setWidth`/`setHeight`.
- Those values come from the style sheet (`getIntProperty`) and from text widths
  (`getStringWidth`).
- The scrollbar's grip shows the rows in view.

**Checked against the hardware:** captured frames in `out/mk3-reference/scales/`
(Keyboard Main/Minor touched, Chords Harmonizer and Chord Set) match except for the
header's level.

## Not yet

- **Maschine's user chord files:** user chord sets (JSON under
  `~/Library/Application Support/Native Instruments/Shared/User Chords/`) are not read.
- **Other MIDI input:** chords are made for the pads only, not for notes from a MIDI
  keyboard (Maschine's Guide, Easy and Learn key modes).
- **Per-group settings:** the scale settings are global in DECKARD. In Maschine each
  group keeps its own, saved with the project.
